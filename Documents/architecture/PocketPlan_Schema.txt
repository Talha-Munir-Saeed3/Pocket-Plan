=============================================================================
ACTIVE COLLECTIONS (USED BY CURRENT ROUTERS)
=============================================================================

1) transactions
   Used by:
   - POST /transactions
   - GET /transactions
   - GET /transactions/recent
   - GET /transactions/history
   - GET /reports/summary (reads)

   Core fields:
   - user_id (string, required)
   - account_id (string, required)
   - type (expense|income|transfer|borrow|lend|savings, required)
   - amount (number > 0, required)
   - currency (string, default PKR)
   - category (required only for expense)
   - description (optional)
   - notes (optional)
   - date (datetime)
   - to_account_id (required for transfer)
   - contact_name (required for borrow/lend)
   - is_recurring (bool)
   - recurring_frequency (required only if recurring)
   - parent_transaction_id (optional)
   - savings_action (required for savings)
   - savings_goal_id (required for savings)
   - target_goal_id (required only for savings transfer)
   - created_at, updated_at


2) budgets
   Used by:
   - POST /budgets (upsert by user_id + account_id + month + year)
   - GET /budgets
   - GET /budgets/current
   - GET /reports/summary (reads)

   Core fields:
   - user_id (string, required)
   - account_id (string, required)
   - month (1-12, required)
   - year (2000-2100, required)
   - total_budget (number > 0, required)
   - total_spent (number >= 0)
   - savings_goal (number >= 0, optional)
   - savings_current (number >= 0)
   - category_limits (array)
     - category (must be valid expense category)
     - limit (number > 0)
     - spent (number >= 0)
     - alert_sent (bool)
   - created_at, updated_at


3) savings_goals
   Used by:
   - POST /savings-goals
   - GET /savings-goals
   - PATCH /savings-goals/{goal_id}

   Core fields:
   - user_id (string, required)
   - account_id (string, optional)
   - name (string, required)
   - target_amount (number > 0, required)
   - current_amount (number >= 0)
   - monthly_contribution (number >= 0)
   - target_date (datetime, optional)
   - is_primary (bool)
   - is_active (bool)
   - created_at, updated_at


4) Health checks (no collection)
   - GET /health
   - GET /health/db (pings DB)


5) Reports (derived data)
   - GET /reports/summary
   Reads transactions + budgets and returns aggregated values.

=============================================================================
FRONTEND-ADMIN STATUS (WHY YOU DO NOT SEE ADMIN TABLES IN MONGO)
=============================================================================

Frontend-Admin pages currently render local mock arrays:
- Payments page: static Payment[] list in React state
- Support page: static SupportTicket[] list in React state
- Users page: static User[] list in React state

Current implication:
- No backend admin routes are connected for these pages.
- No admin collections are created/updated in Mongo from Frontend-Admin yet.

If you want admin data in Mongo, next step is to add backend admin routers such
as:
- /admin/payments
- /admin/support-tickets
- /admin/users
and then connect Frontend-Admin service layer to those APIs.
